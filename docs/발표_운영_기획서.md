## 1. 아이템 한 줄 정의

## 2. 이번 발표에서 이기는 법

평가자는 두 가지만 봅니다.

1. **"이걸 실제로 쓸 수 있나"** → 화면이 돌아가는가, 흐름이 자연스러운가
2. **"이게 돈이 되나"** → 학교 단위 손익이 서는가, 가격 근거가 있는가

**따라서 이번 주에 하지 않는 것**: 해외 분석, PEST 상세, 3개년 재무 추정, TAM-SAM-SOM 3단 산출 — 전부 백업/부록으로 강등.
**이번 주에 하는 것**: 프로토타입 제작 + 학교 단위 손익 + 사용성 테스트.

## 3. 프로토타입 정의 — 5화면

| # | 화면 | 핵심 동작 | 데모에서 보여줄 한 마디 |
| :--- | :--- | :--- | :--- |
| ① | 입력 | 학교 선택 → 범위·부교재·기출 유형 태그 체크 | "3분이면 끝납니다" |
| ② | 프로필 확정 | 같은 학교 태그 2건 일치 → 학교 프로필 카드 생성 | "입력을 서로 검증합니다" |
| ③ | 세트 조립 | 진단 → 매일 세트 → 파이널 모의 타임라인 | "우리 학교 시험에 맞춰 조립" |
| ④ | 오답 → 해설 | 오답 문항 클릭 → 강의 클립·판서 해설 → 유사 문항 | **하이라이트** |
| ⑤ | 적중 리포트 | 시험 후 태그 회수 → 적중률 → 다음 학기 개선 | "쓸수록 정확해집니다" |

**제작 방식**: 정적 웹 목업(HTML) + 목업 데이터. **백엔드 붙이지 않음** (5일 안에 발표 리스크만 커짐).
**목업 데이터 원칙**: 목업 학교 1곳을 실제로 지정(학교명·부교재명 구체적으로), 데이터는 "예시" 명시.
**백업**: 수요일 밤 3분 데모 영상 녹화 필수.

## 4. 비즈니스 모델 — 숫자 5개만

학교 단위로 계산하는 것이 핵심. **원가가 학생 수가 아니라 학교 수에 붙습니다.**

| 항목 | 계산식 | 예시 가정 (검증 필요) |
| :--- | :--- | :--- |
| 객단가 | 학기 패스 1인 | 15만 원 / 학기 |
| 학교당 콘텐츠 원가 | 문항 수 × (변형 200원 + 검수 인건비) | 300문항 × 700원 = 21만 원 |
| 학교당 운영·CS | 파트너·CS 고정비 | 30만 원 / 학기 |
| 채널 수수료 | 매출 × 파트너 리베이트율 | 20% |
| **BEP 학생 수** | (콘텐츠+운영) ÷ (객단가×(1−수수료율)) | (21+30) ÷ 12 = **약 4.3명** |

**승부수 한 줄**: *"학교당 5명만 모이면 손익분기 → 비학군지 소규모 학교도 사업성이 있다."*
→ 이게 성립해야 "대형사가 왜 못 하는가(학교당 모수가 작아서)"에 대한 답이 완성됨.

**가격 앵커**: 학원 월 56만 원 ↔ 인강 월 13.5만 원 → **사이 가격대에 학기 패스**를 놓는다.

**이번 주 반드시 확인할 질문**: *"한 학교에서 5명을 모을 수 있는가"* — UT·인터뷰에서 직접 물어볼 것.
